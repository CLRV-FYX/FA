# FA 互操作：调用 C / C++ / Python / Java

> 互操作的分册。**[08_完全教程.md](08_完全教程.md) 的 §19–§21** 是同一批内容的完整版（含 `use lib` 运行时 dlopen、C++ shim、内嵌汇编）。
> **不想手写 `use c` 声明**：`fa bind 头文件.h --lib 库 -o 绑定.fa` 从 C 头文件自动生成，
> 结构体布局用真 C 编译器量（`sizeof` / 每个字段的 `offsetof` 逐个对过），量不到的写明原因，
> 不悄悄少东西 —— 见 **[§30 跟世界上的库打交道](08_完全教程.md#30-跟世界上的库打交道fa-bind-与真实-c-库)**。
> FA 自己的标准库（`stdlib/fs.fa` / `time.fa` / `re.fa`）底下调的 C 声明
> `stdlib/c/libc.fa` 就是 `fa bind` 生成的。

FA 的设计目标之一就是"**能调用一切**"。四条链路全部可用，且都不需要手写胶水代码。

| 目标 | 语法 | 机制 | 需要什么 |
|---|---|---|---|
| C | `use c "头文件":` | 直接生成 `call` 指令 | 系统 libc / 任何 .so |
| C++ | `use cxx "头.hpp" lib "lib.so":` | 自动生成 `extern "C"` shim，用 g++ 编译 | g++ + 你的库 |
| Python | `use py` | 进程内嵌入 CPython | libpython（通常已随 python3-dev 安装） |
| Java | `use java` | 进程内嵌入 JVM（JNI） | JDK（libjvm.so） |

## 1. C：零胶水，直接声明直接调

```fa
use c "stdio.h":
    fn printf(fmt: *u8, ...) -> i32
    fn malloc(n: u64) -> *u8
    fn free(p: *u8)
    fn strlen(s: *u8) -> u64

fn main() -> i64:
    printf("C 说: %d %s %.2f\n", 42, "ok", 3.14159)
    let p = malloc(64)
    printf("地址: %p\n", p)
    free(p)
    print("strlen:", strlen("hello"))
    return 0
```

要点：

- 声明写在 `use c "头文件名":` 的缩进块里，**不需要写函数体**（写了 `;` 或什么都不写都行）。
- 类型对应关系：

  | FA | C |
  |---|---|
  | `i8/i16/i32/i64` | `int8_t/int16_t/int32_t/int64_t` |
  | `u8..u64` | `uint8_t..uint64_t` |
  | `f32/f64` | `float/double` |
  | `bool` | `bool`（1 字节） |
  | `*T` / `*u8` | `T*` / `char*` |
  | `str` | **自动转成 `char*`**（NUL 结尾） |

- 变参函数用 `...` 声明，调用时 `al` 寄存器由编译器自动填好。
- 浮点变参会按 C 规则提升为 `double`，`str` 变参会转成 `char*`。
- 链接需要的库：`use c "..." lib "m"`（`lib` 后跟 `-l` 的名字或 `.so` 路径）。

### 字符串：两个方向都自动转

`FaStr` 的内存布局是 `{ rc, len, data[] }`，所以**绝不能**把对象指针直接交给 C。
编译器在 extern 调用的边界上自动转换：

| 方向 | 声明写法 | 编译器做的事 |
|---|---|---|
| FA → C | `fn strlen(s: str) -> u64` | 传 `fa_str_cstr(s)`，即 `s->data`（FA 的字符串总是 NUL 结尾） |
| C → FA | `fn strdup(s: str) -> str` | 拿到 `char*` 后调 `fa_str_from_cstr` **拷贝**成一个真正的 FA 字符串 |
| C → FA（不拷） | `fn getenv(n: str) -> *u8` | 原样拿到裸指针；`print(p)` 会按 C 字符串打印，`str(p)` 拷成 FA 字符串 |

```fa
use c "string.h":
    fn strlen(s: str) -> u64
use c "stdlib.h":
    fn getenv(name: str) -> *u8
    fn strdup(s: str) -> str

print(strlen("你好FA"))        # 8（UTF-8 字节数）
let s = strdup("拷回来的")      # s 是 FA 字符串，能 .len() / 插值 / 比较
let h = getenv("HOME")         # h 是 *u8
print(h)                       # 按 C 字符串打印
print(str(h).len())            # 或者拷成 FA 字符串再用
```

> 用 `-> str` 最省事，但它**总是拷贝**一份，C 侧那块 `malloc` 出来的内存就没人释放了
> （`strdup` 这类函数会泄漏一次）。要自己 `free`，就声明成 `-> *u8`，用完再 `str(p)`。
>
> 其它指针（`*i64`、`*Point`）打印出来仍是地址 —— 只有 `*u8` 被当作 `char*`。

### 传结构体给 C

FA 的 struct / enum / 数组在 ABI 里就是「指向它的指针」，而 C 的
`void draw(Point p)` 是按值收的（16 字节进 `rdi:rsi`），两边对不上只会读到垃圾。
所以**只支持按指针传**，C 侧也要声明成指针：

```fa
use c "mylib.h":
    fn draw_point(p: *Point) -> void      # C 侧写 void draw_point(Point *p)
```

写错了不会静默出错，编译期就会拦住：

```
类型错误 (行 6, 列 8): extern 函数 'draw' 的参数 'p' 是 Point（按值）。
C 互操作只支持按指针传结构体/枚举/数组：FA 侧写 `p: *Point`，C 侧写 `Point *p`
```

按值**返回**结构体同理（C 用 `rdx:rax` 或内存，FA 用 sret 指针约定）：
让 C 函数把结果写进指针参数，FA 侧声明成 `-> void` 再传 `&out`。

FA 的容器（`Vec` / `Map`）在 extern 声明里也会被拒 —— C 侧没有这个类型，
请传 `*T` 加一个长度参数。

## 2. C++：自动生成 shim

给一个普通的 C++ 库（随便用 class / 模板 / STL）：

```cpp
// cpp/mathlib.hpp
#pragma once
int      add_ints(int a, int b);
double   mean(const double* arr, int n);
int64_t  fact(int n);
```

```fa
use cxx "cpp/mathlib.hpp" lib "cpp/libmathlib.so":
    fn add_ints(a: i32, b: i32) -> i32
    fn mean(arr: *f64, n: i32) -> f64
    fn fact(n: i32) -> i64

fn main() -> i64:
    print("C++ add_ints(20,22) =", add_ints(20, 22))    # 42
    print("C++ fact(20)        =", fact(20))             # 2432902008176640000
    let d: [f64; 3] = [1.0, 2.0, 9.0]
    print("C++ mean            =", mean(&d[0], 3))       # 4.0
    return 0
```

编译器会自动生成下面的包装代码并用 **g++** 编译它，你完全不用管：

```cpp
extern "C" int32_t fa_add_ints(int32_t a0, int32_t a1) { return add_ints(a0, a1); }
extern "C" double  fa_mean(double* a0, int32_t a1)     { return mean(a0, a1); }
extern "C" int64_t fa_fact(int32_t a0)                 { return fact(a0); }
```

编译 C++ 库：

```bash
g++ -O2 -std=c++17 -fPIC -shared cpp/mathlib.cpp -o cpp/libmathlib.so
```

> C++ 模板 / 重载需要在头文件里提供**非模板的包装函数**（因为 `extern "C"` 不能导出模板），
> 就像上例的 `twice_int` 那样。

## 3. Python：整个生态都是你的

`use py` 会把 **CPython 嵌入**你的进程。所以 numpy、pandas、torch、requests…… 一切 Python
扩展库都能用，而且是**同进程调用**，没有 subprocess 开销。

```fa
use py

fn main() -> i64:
    py.exec("print('  [python] 你好，我是 CPython')")

    # 1) 直接求值
    let r = py.eval("2 ** 100")
    print("2**100 =", r.to_str())

    # 2) 导入模块并调用
    let math = py.import("math")
    let args = Vec<pyobj>[py.from_f64(2.0)]
    let sq = math.attr("sqrt").call(args)
    print("math.sqrt(2) =", sq.to_f64())

    # 3) 用 Python 处理字符串再拿回来
    let s = py.eval("'FA' + '-' + str(2026)")
    print(s.to_str())                       # FA-2026

    # 4) 多行 Python：直接用 numpy
    py.exec("""
import numpy as np
a = np.arange(10)
print('  [python] numpy 求和 =', int(a.sum()))
""")

    # 5) FA 的数据交给 Python 算完再取回
    let total = 0
    let i = 0
    while i < 100:
        total = total + i
        i = i + 1
    let dbl = py.eval("lambda x: x * 2").call(Vec<pyobj>[py.from_i64(total)])
    print("FA 算的 0..99 求和 =", total, "，Python 翻倍 =", dbl.to_i64())
    return 0
```

### API

| 写法 | 说明 |
|---|---|
| `py.exec(code)` | 执行语句（支持三引号多行） |
| `py.eval(expr)` | 求值表达式，返回 `pyobj` |
| `py.import(name)` | 导入模块 |
| `py.from_i64(n)` / `from_f64(x)` / `from_str(s)` / `from_list(v)` | FA → Python |
| `obj.attr("name")` | 取属性 / 方法 |
| `obj.call(Vec<pyobj>)` | 调用（参数放在 `Vec<pyobj>` 里） |
| `obj.to_str()` / `to_i64()` / `to_f64()` | Python → FA |

**内存**：每个 `pyobj` 由 FA 的引用计数自动 `Py_DECREF`，无需手动管理。

## 4. Java：JDK 与全部 jar

`use java` 会把 **JVM 嵌入**你的进程（JNI）。

```fa
use java

fn main() -> i64:
    # 1) 静态方法（类名可用点分写法，编译器自动转成 JNI 的 java/lang/Math）
    let math = java.class("java.lang.Math")
    print(java.call_i64(math, "max", "(II)I", 3, 7))         # 7
    print(java.call_f64(math, "sqrt", "(D)D", 16.0))         # 4.0

    # 2) 创建对象 + 实例方法
    let sb = java.new(java.class("java.lang.StringBuilder"), "()V")
    sb.jcall_void("append", "(Ljava/lang/String;)Ljava/lang/StringBuilder;",
                  java.str("FA + Java"))
    print(sb.jcall_obj("toString", "()Ljava/lang/String;").to_str())

    # 3) 集合类
    let list = java.new(java.class("java.util.ArrayList"), "()V")
    list.jcall_void("add", "(Ljava/lang/Object;)Z", java.str("A"))
    print(list.jcall_i64("size", "()I"))                     # 1
    return 0
```

### 签名怎么来？

`javap -s java.lang.Math` 会打印出每个方法的 JNI 签名：

```
public static int max(int, int);
  descriptor: (II)I
```

常用的：`(II)I`、`(D)D`、`()V`、`(Ljava/lang/String;)V`、`()Ljava/lang/String;`。

### 返回值类型表

| 你调用 | Java 返回类型 |
|---|---|
| `call_i64` / `jcall_i64` | `I J S B C Z`（会自动按签名取正确宽度，不会读错） |
| `call_f64` / `jcall_f64` | `D F` |
| `call_obj` / `jcall_obj` | `L...;` 或 `[`（数组） |
| `call_void` / `jcall_void` | `V` |

### 用第三方 jar

```fa
use java
fn main() -> i64:
    java.init("-Djava.class.path=.:lib/gson.jar")     # 可选：指定 classpath
    let c = java.class("com.google.gson.Gson")
    ...
    return 0
```

## 5. 运行时动态加载（`use lib`）

不想在编译期链接、希望运行时才加载某个 `.so`：

```fa
use lib "./plugins/libawesome.so":
    fn awesome_init() -> i32
    fn awesome_compute(x: i64) -> i64

fn main() -> i64:
    print(awesome_init())
    print(awesome_compute(7))
    return 0
```

FA 会在程序启动时 `dlopen` 这个库并绑定符号；找不到就明确报错。

## 6. 常见问题

**Q：C 的 `printf` 与 FA 的 `print` 输出顺序会乱吗？**
不会。FA 在每次刷新自己的输出缓冲之前会先 `fflush(stdout)`，两者严格按程序顺序出现。

**Q：调用 Python/Java 会有性能损失吗？**
只有跨语言调用本身的开销（微秒级）。把大批量计算留在 FA 或 Python 内部做，
不要在内层循环里反复跨语言即可。

**Q：Python 的 GIL？**
FA 在初始化时释放 GIL（采用 CPython 的嵌入惯例），多次调用由 CPython 自己管理。

**Q：找不到 libpython / libjvm？**
运行 `fa version`，它会打印探测到的 CPython 与 JVM 路径。
安装：`apt install python3-dev default-jdk`。
