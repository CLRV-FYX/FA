# FA 编译器架构

给想读懂 / 改进编译器的人。整体路线是 **Python 引导 → 直出 x86-64 汇编 → 后期自举**。

```
   .fa 源码
      │
      ▼  lexer.py       词法：缩进 / 大括号双模式，字符串插值切分
   Token 流
      │
      ▼  parser.py      语法：混合缩进块与 {} 块
   AST (ast.py)
      │
      ▼  sema.py        语义：类型检查、重载决议、内建函数/方法表
   AST + 符号表
      │
      ▼  codegen.py     AST → 线性 IR（含引用计数插入、所有权转移）
   IR (ir.py)
      │
      ├── regalloc.py   线性扫描寄存器分配 + 循环回边活性扩张
      │
      ▼  asmgen.py      IR → x86-64 GNU as（Intel 语法）
   .s 汇编
      │
      ▼  GNU as + gcc   （C++ 互操作时额外用 g++ 编 shim）
   可执行文件
```

---

## 1. 词法（`lexer.py`）

- **双模式**：行首缩进变化产生 `INDENT` / `DEDENT`；遇到 `{` 则进入大括号模式，
  `;` 作为语句分隔符。两种模式由 `in_braces` 计数器切换。
- `//` 与 `#` 都是行注释；`/* */` 是块注释。
- 字符串在词法阶段就被 `split_interpolation()` 切成"字面片段 / 表达式片段"，
  因此 `"结果是 {a + b}"` 不需要运行时解析。
- 支持三引号多行字符串 `"""..."""`，换行不产生 `NEWLINE`，不影响缩进计算。

## 2. 语法（`parser.py`）

- 递归下降。运算符优先级表 `BIN_PREC` 沿用 C 的相对顺序。
- `fn` 的函数体既可以是缩进块（`fn f():`），也可以是 `{ }` 块。
- `for` 支持三种形式：`for x in 可迭代`、`for x in 0..n`，以及 C 风格 `for (init; cond; step)`。
- `use c / cxx / py / java / lib` 在语法层被识别为 `UseDecl`。

## 3. 语义（`sema.py`）

- 类型系统见 `types.py`：`kind` 决定大类（int/float/str/vec/map/struct/enum/fn/ptr/arr/bool）。
- `layout_struct()` / `layout_enum()` 计算字段偏移与总大小。
- 内建函数 `BUILTIN_FNS` 与内建方法 `BUILTIN_METHODS` 两张表驱动类型检查。
- 引用计数的 **kind 编号**（`fa_runtime.h` 中必须一致）：
  `0=无 1=str 2=vec 3=map 4=pyobj 5=jobj 6=box`；
  含引用字段的结构体用 `1000 + desc_id`。

## 4. 中间表示（`ir.py` + `codegen.py`）

线性 IR，指令形如 `op dst, args, extra, ty`：

| 指令 | 用途 |
|---|---|
| `MOV` / `LOAD` / `STORE` / `LEA` | 数据搬运与内存访问 |
| `BIN` / `UN` / `CMP` | 运算与比较 |
| `CONV` / `BITCAST` | 数值转换 / 同一 64 位数据的类型重解释 |
| `CALL` / `CALLPTR` | 调用（栈上传参由后端展开） |
| `LABEL` / `JMP` / `BR` / `RET` | 控制流 |
| `ALLOCA` / `MEMCPY` / `ZERO` | 栈空间与块复制 |
| `RC_INC` / `RC_DEC` | 引用计数 |
| `ASM` | 原样插入汇编 |

**所有权模型**（`codegen.py`）：

- `owned_ids` 集合记录"本语句新建的、需要释放的引用"，`take_owned()` 实现所有权转移
  （`let x = f()` 时不再多做一次 `rc_inc`）。
- 从变量/字段读出来的是**借用**，绝不会被登记为 owned —— 这是正确性的关键
  （早期版本曾因此造成堆破坏，见 `tests/cases/026_stdlib.fa`）。
- 容器元素的引用计数**完全交给运行时**（`fa_vec_push/set`、`fa_map_set` 内部完成新旧值的增减）。

## 4.5 中端优化（`opt.py`）

在寄存器分配之前、IR 还是「虚拟寄存器 + 线性指令表」时运行。

**循环不变量外提（LICM）**

1. 用**回边**（跳向更靠前位置的 `JMP` / `BR`）识别循环，最内层优先。
2. 只有**单一定义**的临时变量才允许外提 —— 变量（`let` 声明的名字）在循环里会
   被反复赋值，它的 `Temp` 有多处定义，天然被排除。
3. 内存读取的外提需要别名分析，核心假设是：
   > 通过 `LOAD` 取出的指针指向**另一个对象**，不会与宿主对象的头部字节重叠。

   这对 FA 的所有容器都成立：Vec/Map 的元素缓冲区是独立 `malloc` 出来的，
   结构体里的指针字段指向别的对象。而通过 `LEA` 取到的指针（数组元素、结构体字段）
   指向宿主对象**内部**，所以写它会同时污染宿主对象。
   写入集合记录 `(基址, 偏移)`，常量偏移之间还能互相区分。
4. 未知副作用的函数调用「污染一切内存」，直接放弃该循环的 `LOAD` 外提；
   但保证不返回的运行时函数（越界报错、panic）例外 —— 执行不到调用点之后。
5. 外提后插一个 `JMP pre / LABEL pre / <被外提的指令>` 前插块，
   并把循环外指向循环头的跳转改写为指向前插块（循环内的回边保持不变）。

> 踩过的坑：最初只检查 `LOAD` 的**基址**是否不变，漏掉了 `extra` 里作为偏移的
> 另一个 `Temp`，于是 `for x in a` 里「取元素」被错误外提、读到未初始化的下标
> （`tests/cases/008_array.fa` 段错误）。现在基址与偏移都要求不变。

## 5. 寄存器分配（`regalloc.py`）

- 线性扫描（linear scan），可分配寄存器：`rbx r12 r13 r14 r15 r10 r11`；
  浮点 `xmm0-xmm7`；暂存寄存器 `rax rcx rdx rsi rdi r8 r9`。
- `extend_for_loops()` 对回边做不动点扩张，但**只扩张真正跨越循环头的区间** ——
  完全生灭在循环体内部的临时值不扩张，否则会白白耗尽寄存器（这一条带来了
  循环基准 2 倍以上的提速）。
- 跨调用存活的值保存到栈上的 save area（`emit_call_saves`）。
- **复制合并**：`COPY_LIKE_OPS = MOV / BIN / UN / SHIFT` 中，
  若源值在本条指令之后即死，目标直接复用源的寄存器（`CONV` 会改值，绝不合并）。
- **寄存器池分类**：跨调用存活的值优先取 `rbx/r12-r15`（免得每次调用都 save/restore），
  不跨调用的值优先取 `r10/r11`（免得函数开头 push）。

## 6. 汇编生成（`asmgen.py`）

- `.intel_syntax noprefix`，System V AMD64 调用约定。
- **栈帧布局**：
  ```
  push rbp; mov rbp,rsp
  push <被调用者保存寄存器>...      ; k 个
  sub rsp, F                        ; F ≡ 8k (mod 16)，保证 call 处 rsp 16 字节对齐
  ```
  尾声必须是 `lea rsp,[rbp-8k]` 后**逆序** pop，再 `pop rbp; ret`。
- **循环头 16 字节对齐**（`.p2align 4`，等价于 gcc `-falign-loops`）。
  同一段循环仅因起始地址不同实测可差 **40% 以上**：取指/解码按 16/32 字节窗口工作，
  跨窗口的循环头会持续掉速。循环通过回边自动识别。
- **分支布局**：`_fallthrough_labels()` 收集「自然落到的那批标签」（顺带完成相邻标签合并）。
  若 `BR` 的真分支就是下一条指令，就把条件取反、只留一条跳转；
  假分支是下一条指令时直接省掉那条 `jmp`；`jmp` 的目标就是下一条指令则整条删除。
- **比例变址**：`extra=(下标 Temp, 比例)` 直接生成 `[base + idx*scale]`，
  容器元素访问因此省掉一条 `imul`（常量下标则折进位移量）。
- **调用结果留在 rax**：若返回值只被紧邻的下一条指令用一次，就不搬到
  被调用者保存寄存器（`_find_rax_vals()`）。递归密集的代码里每条都算数。
- **目标驱动代码生成**（`codegen.py` 的 `hint` 机制）：赋值 / `let` 把「结果该写到哪个
  `Temp`」作为提示传给**最外层**表达式节点（进入子表达式前先清空，防止被抢走），
  `x = x + 1` 因此直接生成 `add`。
  后端配套修掉了 `d == b` 的隐患（`x = 10 - x` 这类会让 `mov d, a` 先冲掉 `b`）。
- 窥孔优化：
  - `CMP` + `BR` 折叠成 `cmp` + 条件跳转（条件结果仅被该 BR 使用且两者相邻时）
  - 除以 2 的幂 → `sar` + 偏置修正（C 语义的截断除法）
  - 加减常量 → 一条 `lea`（1 个 uop，省掉 `mov`）
  - 消除自赋值 `mov r, r`
  - 立即数不能直接 `movsd` / `cmp` 双立即数 → 先装入暂存寄存器
  - 已知被调函数不是可变参数时省掉 `mov eax, 0`（`al` 只在可变参数调用里有意义）

## 7. 运行时（`runtime/`）

| 文件 | 内容 |
|---|---|
| `fa_runtime.c` | 内存分配、字符串、Vec/Map、引用计数、I/O 缓冲 |
| `fa_syscall.S` | 手写汇编的 `write / read / open / exit` 等系统调用封装 |
| `fa_python.c` | 内嵌 CPython（`#include <Python.h>`），未安装时自动退化为桩实现 |
| `fa_jvm.c` | 内嵌 JVM（JNI），未安装时自动退化为桩实现 |

**字符串布局**：`{ i64 rc; i64 len; char data[] }`，`rc = -1` 表示永生（.rodata 里的字面量）。

**Vec 布局**：`{ i64 rc; i64 len; i64 cap; i64 kind; uint64_t *data; i64 esz; i64 sgn }`。
`data` 必须保持在偏移 **32** —— `codegen.py` 内联的 `get` / `set` / `len` 直接用这个硬编码偏移。
`esz` 是元素存储宽度（1/2/4/8），`sgn` 表示窄元素是否有符号（决定零扩展还是符号扩展）。
读写一律走 `vec_load()` / `vec_store()` 两个 helper，对外 ABI 仍是 `uint64_t`。

**模块初始化**：`.init_array` 段里注册 `fa_py_init`（Python）。
JVM **不能**在 `.init_array` 里启动（libjimage 会在进程尚未就绪时崩溃），
改为首次调用 `java.*` 时惰性创建。

## 8. 构建流程（`driver.py`）

1. 前端：源码 → 汇编字符串
2. `as` 汇编成 `.o`
3. 若用了 `use cxx`：生成 `extern "C"` shim，用 `g++` 编译
4. 生成 `main` shim（把 `main` 的 `argc/argv` 转交给 `fa_main`）
5. `gcc` 链接：运行时 `.o` + 用户 `.o` + 按需的 `libpython` / `libjvm`

## 9. 自举计划（下一步）

编译器本身是用 Python 写的引导版本（`compiler/falang/`）。
等 FA 语言特性足够（模块系统、更完整的数据结构、文件 I/O、正则等），
就用 FA 重写一份 `compiler/src/*.fa`，用引导版本编译它自己 —— 那之后 FA 就完全自持了。

在此之前，引导版本已经能**直接产出不依赖 Python 的原生可执行文件**，
终端用户完全不需要装 Python 来运行 FA 程序（只有编译时需要）。
