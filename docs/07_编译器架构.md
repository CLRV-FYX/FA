# FA 编译器架构

给想读懂 / 改进编译器的人。整体路线是 **Python 引导 → 直出 x86-64 汇编 → 后期自举**。

```
   .fa 源码
      │
      ▼  lexer.py       词法：缩进 / 大括号双模式，字符串插值切分
   Token 流
      │
      ▼  parser.py      语法：混合缩进块与 {} 块
   AST (ast.py)
      │
      ▼  sema.py        语义：类型检查、重载决议、内建函数/方法表
   AST + 符号表
      │
      ▼  codegen.py     AST → 线性 IR（含引用计数插入、所有权转移）
   IR (ir.py)
      │
      ├── regalloc.py   线性扫描寄存器分配 + 循环回边活性扩张
      │
      ▼  asmgen.py      IR → x86-64 GNU as（Intel 语法）
   .s 汇编
      │
      ▼  GNU as + gcc   （C++ 互操作时额外用 g++ 编 shim）
   可执行文件
```

---

## 1. 词法（`lexer.py`）

- **双模式**：行首缩进变化产生 `INDENT` / `DEDENT`；遇到 `{` 则进入大括号模式，
  `;` 作为语句分隔符。两种模式由 `in_braces` 计数器切换。
- `//` 与 `#` 都是行注释；`/* */` 是块注释。
- 字符串在词法阶段就被 `split_interpolation()` 切成"字面片段 / 表达式片段"，
  因此 `"结果是 {a + b}"` 不需要运行时解析。
- 支持三引号多行字符串 `"""..."""`，换行不产生 `NEWLINE`，不影响缩进计算。

## 2. 语法（`parser.py`）

- 递归下降。运算符优先级表 `BIN_PREC` 沿用 C 的相对顺序。
- `fn` 的函数体既可以是缩进块（`fn f():`），也可以是 `{ }` 块。
- `for` 支持三种形式：`for x in 可迭代`、`for x in 0..n`，以及 C 风格 `for (init; cond; step)`。
- `use c / cxx / py / java / lib` 与 `use "文件.fa"` 在语法层都被识别为 `UseDecl`
  （`kind` 分别是 c/cxx/py/java/lib/file/std）。
- `parse_block()` 接受**三种块**：`{ ... }`、换行 + 缩进、以及**同一行的单条语句**
  （`Color.Red: return "红"`、`if x > 0: return 1`）。第三种以前会报
  「这里需要一个缩进代码块」，而它恰恰是 `match` 最常见的写法。
- `match x { ... }` 的花括号形式需要一点消歧：解析主语时置起 `no_struct_lit`，
  否则 `x {` 会被当成结构体字面量吃进去，报「期望 'NAME'，实际得到 'NUM'」。
- 少写一个 `}` 时报「缺少 '}'（块未闭合）」，而不是一路吃到 EOF 再说
  「无法解析的表达式起始 token 'None'」。
- **头部表达式**（`if` / `while` / `for ... in` / `match` 的条件与主语）统一走
  `parse_head_expr()`：解析时置起 `no_struct_lit`。否则 `if done { ... }` 里的
  `done {` 会被当成结构体字面量的开头，报一句莫名其妙的「期望 'NAME'，实际得到 'true'」。
- `if` / `match` 也能出现在**表达式位置**（`_parse_primary` 里直接转给 `parse_if` /
  `parse_match`），两种位置共用同一套解析代码。
- 所有 `parse_*` 出口都过一层 `stamp()`，把 token 的行列写进节点 ——
  诊断质量全靠这个（顶层声明以前没有位置，报错都是「行 0, 列 0」）。
- 字符串插值里的引号由**词法**处理：`"` 扫描时记着 `{}` 的嵌套深度，
  深度 > 0 时遇到的引号属于内层字面量，整体吞掉（`"{m["k"]}"` 因此可用）。

## 3. 语义（`sema.py`）

- 类型系统见 `types.py`：`kind` 决定大类（int/float/str/vec/map/struct/enum/fn/ptr/arr/bool）。
- `layout_struct()` / `layout_enum()` 计算字段偏移与总大小。
- 内建函数 `BUILTIN_FNS` 与内建方法 `BUILTIN_METHODS` 两张表驱动类型检查。
- **运行顺序**（`Sema.run()`）：
  0. `expand_file_uses()` —— 把 `use "x.fa"` 递归展开成那个文件的顶层声明，
     用 `realpath` 去重防循环导入；文件不存在 / 写了 `as` 别名 / `use std.xxx`
     都在这里报错。展开之后，后面的布局、注册、检查流程一概不用改。
  1. 顶层重名检查（两个同名 `fn` 以前要拖到汇编器才报 `symbol already defined`）。
  2. `collect_decl()` 收集名字 → 结构体布局 → 枚举布局 → 函数/方法签名 → 函数体检查。
- **递归类型**：`collect_decl()` 先登记一个 `fields = None` 的**空壳** `Type`，
  布局结果就地填回同一个对象（`_fill_in_place`）。这样 `next: *Node` 拿到的是
  同一个壳，稍后自动生效；`resolve_type()` 对指针目标**不触发**按需布局（否则自引用
  会无限递归），对按值引用才触发，并用 `_laying_out` 集合抓住「按值包含自己」。
  以前占位是 `None`，`*Node` 被解析成 `ptr_to(None)`，报「类型 *None 没有字段 'val'」。
- **if / match 作为表达式**（`expr_if` / `expr_match`）：先按语句规则整体检查一遍
  （`self.stmt(e)`，条件、分支、作用域、模式绑定全都复用），再取每个分支的
  **尾表达式**（块里最后一条 `ExprStmt`；最后一条是 `If`/`Match` 时递归下去）统一类型：
  数值取更宽的（有浮点则 `f64`），指针之间互转，`nil` 分支跟随另一边的指针类型，
  以 `return` / `break` / `continue` / `panic` / `exit` 结尾的分支标记 `Block.diverges`
  并跳过。`if` 必须有 `else`，`match` 必须有 `_` 或覆盖枚举全部变体；聚合结果直接拒绝。
- **期望类型下传**：`expr(e, expect=...)` 从 `let` 标注 / 赋值目标 / `return` 传下来，
  空的 `[]` 靠它决定是 `Vec<T>` 还是 `[T; 0]`。
- 下标（`Index`）的类型规则：数组/Vec/str 要整数下标（str 得到 `char` = 字节），
  Map 则按**键类型**检查并得到值类型；`s[i] = c` 会被拒（`str` 不可变）。
- `p.field`（`p: *S`）在语义阶段打上 `auto_deref` 标记，按 `S` 解析字段。
- **extern 调用的边界转换**（`use c / cxx / lib`）：`FaStr` 的布局是 `{rc, len, data[]}`，
  把对象指针直接交给 C，`%s` 打出来就是乱码。所以 `gen_call_fs()` 在 `fs.extern` 时
  对声明为 `str` 的形参走 `fa_str_cstr`（取 `data`，FA 的字符串总是 NUL 结尾），
  对声明为 `str` 的返回值走 `fa_str_from_cstr`（拷成真正的 FA 字符串）。
  以前只有可变参数那条路做了转换。按值收发 struct/enum/数组、以及 FA 容器出现在
  extern 声明里，都在 `register_fn()` 里提前报错（C 侧的 ABI 对不上，运行时只会读到垃圾）。
- `s.cstr()` 的类型是 `*u8` 而不是 `str`：标成 `str` 会让 `let p = s.cstr()`
  对这个裸指针调 `rc_inc`，把字符串数据当对象头写 —— 实测直接段错误。
- 引用计数的 **kind 编号**（`fa_runtime.h` 中必须一致）：
  `0=无 1=str 2=vec 3=map 4=pyobj 5=jobj 6=box`；
  含引用字段的结构体用 `1000 + desc_id`。

## 4. 中间表示（`ir.py` + `codegen.py`）

线性 IR，指令形如 `op dst, args, extra, ty`：

| 指令 | 用途 |
|---|---|
| `MOV` / `LOAD` / `STORE` / `LEA` | 数据搬运与内存访问 |
| `BIN` / `UN` / `CMP` | 运算与比较 |
| `CONV` / `BITCAST` | 数值转换 / 同一 64 位数据的类型重解释 |
| `CALL` / `CALLPTR` | 调用（栈上传参由后端展开） |
| `LABEL` / `JMP` / `BR` / `RET` | 控制流 |
| `ALLOCA` / `MEMCPY` / `ZERO` | 栈空间与块复制 |
| `RC_INC` / `RC_DEC` | 引用计数 |
| `ASM` | 原样插入汇编 |

**所有权模型**（`codegen.py`）：

- `owned_ids` 集合记录"本语句新建的、需要释放的引用"，`take_owned()` 实现所有权转移
  （`let x = f()` 时不再多做一次 `rc_inc`）。
- 从变量/字段读出来的是**借用**，绝不会被登记为 owned —— 这是正确性的关键
  （早期版本曾因此造成堆破坏，见 `tests/cases/026_stdlib.fa`）。
- 容器元素的引用计数**完全交给运行时**（`fa_vec_push/set`、`fa_map_set` 内部完成新旧值的增减）。

**聚合值（结构体 / 枚举 / 数组）的表示约定** —— 改后端前务必读懂这几条：

- 聚合值在 IR 里一律用「**指向它的指针**」表示；`load_ptr()` 对聚合类型返回指针本身，
  但**不能丢掉偏移量**（`es[1]` 需要 `LEA base+16`，否则永远读到第 0 个元素的 tag）。
- Vec 里的结构体/枚举元素存的是**装箱指针**（`box_agg()`），所以 `v[i].字段`、
  `for s in v` 都按指针语义处理；标量元素才是按位存的原始值。
- 浮点元素按 **uint64_t 位模式** 存取（容器 ABI 只有一个 `uint64_t` 通道），
  进出都要 `bitcast`。**常量的 bitcast 必须在 `codegen.bitcast()` 里就地完成**：
  否则优化器把 `BITCAST` 折叠掉之后，调用点看到的是一个 `ty=f64` 的常量，
  按浮点 ABI 放进 `xmm0`，而 `fa_vec_push` 读的是 `rsi` —— 存进去的是垃圾位。
- 方法返回聚合值时用 **sret**：`rdi` = 返回缓冲，`self` 退到 `rsi`，其余整数参数
  从 `rdx` 起（两个「让位」要各让一个，否则整数形参会和 `self` 抢 `rsi`）。
- 方法的 `FnSym.params` **不含** `self`（`register_impl` 过滤掉了）：
  调用点第 i 个实参对应 `fs.params[i]`，被调方 `ptemps` 的下标是 `i + (1 if sret else 0)`。
  这两处以前各差一位，表现为「带参数的方法直接 IndexError」和「多参数方法按错一位的类型转换实参」。
- **if / match 表达式的后端**：`gen_if_chain(..., dst=r)` / `gen_match(s, dst=r)`
  把每个分支的尾表达式 `MOV` 进同一个结果临时变量 `r`（`gen_block_value`）。
  引用计数类型按 `gen_let` 的同一套规则转移所有权：分支里新建的临时引用用
  `take_owned` 交给 `r`，来自变量/字面量的则 `emit_rcinc` 一份 —— 既不泄漏也不双放
  （实测 1000 万次循环里反复产生 str / Vec，RSS 恒定 ~0.9 MB）。
  `Block.diverges` 的分支直接走普通 `gen_block`，不产出值。
  结果是聚合值时 `dst` 换成 `emit_alloca` 出来的栈槽，分支值用 `emit_init_agg`
  移交（新建的转移所有权，借用的拷贝 + 逐字段加引用）；判定要用**尾表达式的类型**，
  因为 alloca 槽自己的 `.ty` 是 `*u8`。
- **分支内的临时引用必须在分支内释放**（`release_new_refs`）：`self.owned` /
  `self.agg_owned` 是**语句级**的表，而 if 表达式的分支只是语句中间的一段 IR。
  分支里产生的中间引用（`"n{i}"` 插值过程中的 `str(i)` 和 concat 结果）若拖到语句
  末尾才 `rc_dec`，走另一条分支的路径上那些寄存器装的是无关的值 ——
  实测把循环下标当对象指针释放，直接段错误。进入分支前记下已有的 id 集合，
  离开时只释放新增的那些（结果 `dst` 除外），条件表达式产生的引用仍留给外层语句
  （它们活跃区间横跨整个 if，寄存器分配器不会在分支里复用）。
  三条产出路径（值即 dst / 聚合 / 标量）共用一个 `try...finally` 收尾，
  少一条就会漏放。
- 遍历（`gen_for`）绑定循环变量的四种情况：range → 下标；Vec → `fa_vec_get`
  （浮点要 bitcast，聚合要绑成指针）；str → `fa_str_byte`；数组 → 标量直接 `LOAD`，
  聚合则 `LEA` + `emit_init_agg` 拷一份到本次迭代的栈槽（作用域退出时照常释放）。

## 4.5 中端优化（`opt.py`）

在寄存器分配之前、IR 还是「虚拟寄存器 + 线性指令表」时运行。

**循环不变量外提（LICM）**

1. 用**回边**（跳向更靠前位置的 `JMP` / `BR`）识别循环，最内层优先。
2. 只有**单一定义**的临时变量才允许外提 —— 变量（`let` 声明的名字）在循环里会
   被反复赋值，它的 `Temp` 有多处定义，天然被排除。
3. 内存读取的外提需要别名分析，核心假设是：
   > 通过 `LOAD` 取出的指针指向**另一个对象**，不会与宿主对象的头部字节重叠。

   这对 FA 的所有容器都成立：Vec/Map 的元素缓冲区是独立 `malloc` 出来的，
   结构体里的指针字段指向别的对象。而通过 `LEA` 取到的指针（数组元素、结构体字段）
   指向宿主对象**内部**，所以写它会同时污染宿主对象。
   写入集合记录 `(基址, 偏移)`，常量偏移之间还能互相区分。
4. 未知副作用的函数调用「污染一切内存」，直接放弃该循环的 `LOAD` 外提；
   但保证不返回的运行时函数（越界报错、panic）例外 —— 执行不到调用点之后。
5. 外提后插一个 `JMP pre / LABEL pre / <被外提的指令>` 前插块，
   并把循环外指向循环头的跳转改写为指向前插块（循环内的回边保持不变）。

> 踩过的坑：最初只检查 `LOAD` 的**基址**是否不变，漏掉了 `extra` 里作为偏移的
> 另一个 `Temp`，于是 `for x in a` 里「取元素」被错误外提、读到未初始化的下标
> （`tests/cases/008_array.fa` 段错误）。现在基址与偏移都要求不变。

## 5. 寄存器分配（`regalloc.py`）

- 线性扫描（linear scan），可分配寄存器：`rbx r12 r13 r14 r15 r10 r11`；
  浮点 `xmm0-xmm7`；暂存寄存器 `rax rcx rdx rsi rdi r8 r9`。
- `extend_for_loops()` 对回边做不动点扩张，但**只扩张真正跨越循环头的区间** ——
  完全生灭在循环体内部的临时值不扩张，否则会白白耗尽寄存器（这一条带来了
  循环基准 2 倍以上的提速）。
- 跨调用存活的值保存到栈上的 save area（`emit_call_saves`）。
- **复制合并**：`COPY_LIKE_OPS = MOV / BIN / UN / SHIFT` 中，
  若源值在本条指令之后即死，目标直接复用源的寄存器（`CONV` 会改值，绝不合并）。
- **寄存器池分类**：跨调用存活的值优先取 `rbx/r12-r15`（免得每次调用都 save/restore），
  不跨调用的值优先取 `r10/r11`（免得函数开头 push）。

## 6. 汇编生成（`asmgen.py`）

- `.intel_syntax noprefix`，System V AMD64 调用约定。
- **栈帧布局**：
  ```
  push rbp; mov rbp,rsp
  push <被调用者保存寄存器>...      ; k 个
  sub rsp, F                        ; F ≡ 8k (mod 16)，保证 call 处 rsp 16 字节对齐
  ```
  尾声必须是 `lea rsp,[rbp-8k]` 后**逆序** pop，再 `pop rbp; ret`。
- **循环头 32 字节对齐**（`.p2align 5`，等价于 gcc `-falign-loops=32`）。
  同一段循环仅因起始地址不同实测可差 **40% 以上**：取指/解码按 16/32 字节窗口工作，
  跨窗口的循环头会持续掉速。循环通过回边自动识别。
  实测（1 亿次算术循环）：不对齐 140 ms → `.p2align 4` 123 ms → `.p2align 5` 98 ms
  → `.p2align 6` 104 ms（还白占 icache），所以取 32 字节。
- **分支布局**：`_fallthrough_labels()` 收集「自然落到的那批标签」（顺带完成相邻标签合并）。
  若 `BR` 的真分支就是下一条指令，就把条件取反、只留一条跳转；
  假分支是下一条指令时直接省掉那条 `jmp`；`jmp` 的目标就是下一条指令则整条删除。
- **比例变址**：`extra=(下标 Temp, 比例)` 直接生成 `[base + idx*scale]`，
  容器元素访问因此省掉一条 `imul`（常量下标则折进位移量）。
- **调用结果留在 rax**：若返回值只被紧邻的下一条指令用一次，就不搬到
  被调用者保存寄存器（`_find_rax_vals()`）。递归密集的代码里每条都算数。
- **调用点实参装配**（`emit_call`）先把所有实参求值到寄存器/立即数，再按 SysV 分类
  （整数 `rdi…r9`、浮点 `xmm0-7`、其余进栈），然后处理**并行搬运冲突**：
  某个实参此刻正待在另一个实参的目标寄存器里（典型是方法里再调函数 ——
  形参 `k` 固定在 `xmm0`，第一个实参也要进 `xmm0`），顺序搬运会把它冲掉
  （实测 `scale(self.x, k)` 算成了 `x*x`）。办法是把冲突值先挪到栈上暂存，
  进栈的实参则**先写**（此时还没有目标寄存器被覆盖）。
  `CALLPTR` 的函数指针同样先求值，并纳入同一套冲突分析（它常待在 `rdi`）。
- **目标驱动代码生成**（`codegen.py` 的 `hint` 机制）：赋值 / `let` 把「结果该写到哪个
  `Temp`」作为提示传给**最外层**表达式节点（进入子表达式前先清空，防止被抢走），
  `x = x + 1` 因此直接生成 `add`。
  后端配套修掉了 `d == b` 的隐患（`x = 10 - x` 这类会让 `mov d, a` 先冲掉 `b`）。
- 窥孔优化：
  - `CMP` + `BR` 折叠成 `cmp` + 条件跳转（条件结果仅被该 BR 使用且两者相邻时）
  - 除以 2 的幂 → `sar` + 偏置修正（C 语义的截断除法）
  - 加减常量 → 一条 `lea`（1 个 uop，省掉 `mov`）
  - 消除自赋值 `mov r, r`
  - 立即数不能直接 `movsd` / `cmp` 双立即数 / `cvtsi2sd` / `movsx` / `not x` 里的 `cmp`
    → 先装入暂存寄存器（`opreg(..., allow_imm=False)`）
  - `mov` 到内存只接受 32 位有符号立即数：放不下的（例如 `fv[0] = 9.5` 内联写元素时
    那个 f64 位模式 4621537642612260864）先 `movabs` 进寄存器
  - 已知被调函数不是可变参数时省掉 `mov eax, 0`（`al` 只在可变参数调用里有意义）

## 7. 运行时（`runtime/`）

| 文件 | 内容 |
|---|---|
| `fa_runtime.c` | 内存分配、字符串、Vec/Map、引用计数、I/O 缓冲 |
| `fa_syscall.S` | 手写汇编的 `write / read / open / exit` 等系统调用封装 |
| `fa_python.c` | 内嵌 CPython（`#include <Python.h>`），未安装时自动退化为桩实现 |
| `fa_jvm.c` | 内嵌 JVM（JNI），未安装时自动退化为桩实现 |

**字符串布局**：`{ i64 rc; i64 len; char data[] }`，`rc = -1` 表示永生（.rodata 里的字面量）。

**Vec 布局**：`{ i64 rc; i64 len; i64 cap; i64 kind; uint64_t *data; i64 esz; i64 sgn }`。
`data` 必须保持在偏移 **32** —— `codegen.py` 内联的 `get` / `set` / `len` 直接用这个硬编码偏移。
`esz` 是元素存储宽度（1/2/4/8），`sgn` 表示窄元素是否有符号（决定零扩展还是符号扩展）。
读写一律走 `vec_load()` / `vec_store()` 两个 helper，对外 ABI 仍是 `uint64_t`。

**模块初始化**：`.init_array` 段里注册 `fa_py_init`（Python）。
JVM **不能**在 `.init_array` 里启动（libjimage 会在进程尚未就绪时崩溃），
改为首次调用 `java.*` 时惰性创建。

## 8. 构建流程（`driver.py`）

1. 前端：源码 → 汇编字符串
2. `as` 汇编成 `.o`
3. 若用了 `use cxx`：生成 `extern "C"` shim，用 `g++` 编译
4. 生成 `main` shim（把 `main` 的 `argc/argv` 转交给 `fa_main`）
5. `gcc` 链接：运行时 `.o` + 用户 `.o` + 按需的 `libpython` / `libjvm`

## 9. 自举计划（下一步）

编译器本身是用 Python 写的引导版本（`compiler/falang/`）。
等 FA 语言特性足够（模块系统、更完整的数据结构、文件 I/O、正则等），
就用 FA 重写一份 `compiler/src/*.fa`，用引导版本编译它自己 —— 那之后 FA 就完全自持了。

在此之前，引导版本已经能**直接产出不依赖 Python 的原生可执行文件**，
终端用户完全不需要装 Python 来运行 FA 程序（只有编译时需要）。
